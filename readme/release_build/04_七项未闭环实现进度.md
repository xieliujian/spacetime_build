## 非真实环境仍需实现的功能

下面列出的是可以在本仓库和 fake/隔离端口中继续完成的代码功能，不依赖真实 SVN、Unity、Jenkins、秘密服务、
供应商 CDN、macOS 或历史客户端。它们与后文的生产环境验收项分开记录。

### 1. CLI 全量生产 handler 与参数编排

本轮已为 `create_production_command_services` 接入当前命令树中的 production handler：

- `plan`、`resource build`：从参数构造 `ApplicationRequest` 和 `BuildContext`，调用注入的 task provider 与
  `BuildResourcesUseCase`，并可写出确定性 BuildManifest；
- `release upload`、`release activate`、`release publish`、`release rollback`：通过严格 codec 读取
  `UploadPlan`、`ReleaseBundle` 和验证凭证，再分阶段调用上传、验证、激活、发布或回滚边界；
- `package build`：构造 `PackageRequest`，读取验证凭证并调用注入的 `PackageClientUseCase`；
- `compatibility dual-run`：校验隔离路径，调用注入的旧系统 runner 并输出验收报告；
- `run status`、`run cancel`、`run resume`：读取持久 `RunRecordRepository`，使用 CAS 记录取消状态；恢复动作
  仍必须由部署组合根显式注入。

这些 handler 已有参数、请求 DTO、服务调用和配置缺失错误边界；资源 task provider、package client、旧系统 runner
和 resume action 不提供时会明确返回配置错误，不使用默认替身冒充生产执行。

### 2. 统一 application composition 注册表

本轮扩展了 `ProductionApplicationServices`，在原有版本、上传、验证、激活、探针和正式构建之外，统一注册并校验：

- `BuildResourcesUseCase` 与资源 task provider；
- `PackageClientUseCase`；
- `RunRecordRepository`、`RunOperations`、旧系统验收服务、旧 runner 和 resume action；
- standalone release 与 run handler 所需的共享对象存储边界。

分支写操作、`art` 操作、平台 builder 的具体部署配置和统一结果 schema 仍待接入；这些能力已有领域模型或隔离执行器，
但尚未虚构成 production composition 已完成。

### 3. Standalone 发布状态与恢复 codec

本轮已补齐独立发布阶段的 CLI 输入和调用边界：

- `ReleaseBundle`、`UploadPlan`、验证凭证通过现有严格、确定性 codec 读取；
- upload/activate/publish/rollback handler 已将文件输入、服务缺失、CAS 冲突和失败结果接入 CLI；
- `run cancel` 使用 current 索引的 generation 做 CAS，避免覆盖并发更新；
- 记录仓库新增 current 索引读取和 schema/路径/身份校验，不把远端入口或秘密原文写入记录。

仍未完成的是上传中断后的通用 reconcile，以及不依赖部署方 action 的自动恢复编排；`run resume` 目前要求显式注入
resume action。

## 下一步关闭条件

每项能力只有同时具备以下证据才可改为 `VERIFIED`：

1. 真实工具或服务的固定版本、地址/目标和权限边界；
2. 隔离输入快照、命令行、退出码和完整脱敏日志；
3. 输出文件、SHA256、协议解析或平台安装/启动验证；
4. 失败、取消、恢复、冲突和回滚路径证据；
5. 可复核的证据 JSON、日志定位、执行人和复核人。

在这些输入未提供前，代码可以继续完善本地执行入口和隔离测试，但文档和 CLI 不得把 `PENDING` 改写成生产可用。
