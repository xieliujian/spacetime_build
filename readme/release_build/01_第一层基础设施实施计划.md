# 正式版本制作第一层基础设施 Implementation Plan

> **For agentic workers:** REQUIRED: Use `superpowers:subagent-driven-development`（有子代理时）
> 或 `superpowers:executing-plans` 执行本计划。所有行为变更严格遵循 RED、GREEN、REFACTOR；
> 步骤使用复选框跟踪。未经用户明确要求不得创建 Git commit。

**Goal:** 实现正式版本制作第一层所需的强类型 TOML 配置、稳定错误载体、脱敏文本日志，
以及可超时、可取消并安全捕获输出的真实本地进程执行能力。

**Architecture:** 新增 `configuration`、`observability`、`ports` 和 `integrations` 四个顶级包。
配置与错误模型保持纯 Python、不可变且无 I/O 副作用；日志只通过统一接口输出 `.log`；外部命令
只能经 `ProcessRunner` Protocol 执行，真实 `subprocess` 细节限制在 `integrations.process`。
现有 `core` 与 `release` 领域包不依赖这些具体适配器。

**Tech Stack:** Python 3.10、`tomli` / `tomli-w`、标准库 `logging`、`subprocess`、
`threading`、`pathlib`，pytest、Ruff、Pyright。

## 2. 文件结构

```text
src/
  configuration/
    __init__.py          # 配置公共 API
    model.py             # BuildConfig、子配置、SecretRef、ResolvedBuildConfig
    loader.py            # 三层 TOML 解析、深度合并、来源摘要
    validator.py         # 未知字段、路径、工具、输出冲突、超时校验
    service.py           # load/validate/save/update/enable/disable/resolve_profile
  observability/
    __init__.py          # 日志公共 API
    context.py           # LogContext 与日志文件定位
    failures.py          # ErrorCode、BuildFailure 及异常映射
    redaction.py         # 字符串、参数、环境和异常文本脱敏
    logger.py            # 统一 Logger Protocol 与事件模型
    handlers.py          # Jenkins 控制台、排他文件和外部流 handler
  ports/
    __init__.py
    process.py           # ProcessRequest/Result、CancellationToken、ProcessRunner
  integrations/
    __init__.py
    process.py           # LocalProcessRunner
tests/
  configuration/
  observability/
  ports/
  integrations/
```

原则：每个模块只承担一个职责；`configuration` 不导入 `integrations`；`ports` 不依赖
`subprocess`；`observability` 不保存秘密原文；`LocalProcessRunner` 只接收参数序列且固定
`shell=False`。
