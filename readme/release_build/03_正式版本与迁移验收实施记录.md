## 已实现链路

### 资源 builder

`src/resource/tasks/unity_asset.py` 固化七类资源任务共用的请求、输入摘要、输出所有权、
依赖保序、Unity 操作和 CAS 提交边界。`map`、`character`、`texture`、`ui`、`particle`、
`audio`、`video` 分别校验自己的输入来源和设置。`src/resource/unity_builder.py` 将这些
类型化操作映射为旧项目兼容 flag，并通过 `UnityBatchRunner` 执行真实 batchmode；它只写
隔离工程输出和日志，不直接提交 CAS 或修改 SVN。

### 正式版本

- `release/versioning.py`：由最终入口计算 version stream，提供 `preview`、`allocate`、
  `mark_ready`、`prepare_activation`、`confirm`、`reconcile`、`abandon`；同一 `build_id`
  幂等，号码单调且不复用，状态可保存在本地 JSON；
- `release/version_layout.py`：按显式入口 key、基础 URL 和 FileListNo 生成规范版本入口；
- `application/formal_release.py`：把 BuildManifest 转换为传输对象和兼容协议输出，构建
  UploadPlan，顺序执行上传、远端回读、版本固化、CAS 激活和确认；
- 版本入口是 CAS replacement，不在普通对象上传阶段伪造为已上传对象；远端验证器只验证
  已上传的不可变对象，激活器负责入口回执摘要。

### 外部探针

`integrations/probes.py` 提供 SVN、Unity、Jenkins、Secrets 和 ObjectStore/CDN 探针，
`JsonProbeEvidenceWriter` 以原子 JSON 写入脱敏摘要。缺少真实端口或输入时返回 `PENDING`，
失败返回 `FAILED`；不会将秘密值、原始日志或凭据 locator 写入证据。

### 历史双跑与 Parser

`compatibility/legacy_acceptance.py` 强制源码快照、历史产物和候选产物位于同一隔离根，
由注入的旧系统 runner 生成候选输出，读取两边文件摘要并执行：

- `assetbundledb_*.txt` 的严格 AssetBundle Parser；
- `file_list_<FileListNo>.txt` 的严格六字段 Parser；
- 按逻辑路径计算 added/removed/changed 差异。

历史目录或旧系统 runner 缺失时只返回 `PENDING`；合成 fixture 通过不等于真实迁移完成。

## 真实验收所需输入

真实验收仍需由部署方显式提供：固定 SVN URL/revision、隔离工作区、Unity 可执行文件和
许可证、Jenkins Job 地址与凭据、秘密服务租约、供应商 ObjectStore/CDN 目标、历史旧系统
输出和旧客户端 Parser 版本。收到这些输入后，必须把探针 JSON、双跑差异、命令退出码、
日志定位和复核人一并归档；在此之前文档和 CLI 输出不得把 `PENDING` 改写成 `VERIFIED`。
