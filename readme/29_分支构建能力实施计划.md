# 分支构建能力 Implementation Plan

> **For agentic workers:** REQUIRED: Use `superpowers:subagent-driven-development` 或
> `superpowers:executing-plans` 逐任务执行；每个 Task 独立完成 RED、GREEN 和回归。

**Goal:** 把旧 SVN 分支复制、externals 重写和工作副本 relocate 拆成可预览、可审计、固定 revision、默认只读的类型化组件。

**Architecture:** `st.build.branch` 负责解析配置、生成不可变 BranchPlan、验证映射和解释执行结果；唯一写 SVN 的实现仍是计划 18 的 `SourceRepositoryAdmin`。branch 不直接运行 svn、不创建 application pipeline，CLI/application 接入仍归计划 26。

**Tech Stack:** Python 3.10、pytest、SVN XML/peg revision 语义、计划 18 SourceProvider/SourceRepositoryAdmin/ObjectStore。

---

## 1. 状态、边界与已确认行为

- 文档状态：**设计与实施计划完成，独立审查通过**。
- 代码状态：**规划中，`st.build.branch` 尚不存在**。
- 只读参考：`branch/copy_svn_project.py`、`rebuild_svn_external.py`、`relocate.py` 及两个 bat 入口。
- 旧能力包括 server-side copy、`svn:externals` 重写、自定义 external 映射和工作副本 relocate。

分支写操作具有高风险，默认模式永远是 plan/inspect。apply 必须显式提供已持久化 plan ID、目标 URL
确认值、固定 expected repository revision 和一次性 mutation ID；不得接受 `HEAD`、任意 svn 子命令、
已存在目标或跨仓库非原子复制。新系统不自动删除已有分支，不修改旧工具目录。

非目标：不定义分支命名审批制度、不迁移 batch 脚本、不自动合并代码、不修改 Jenkins job、不在
本模块编排资源/包体构建。

## 2. 模块结构与领域对象

```text
src/st/build/branch/
  model.py             # BranchSource、BranchTarget、规则和状态
  config.py            # TOML 映射 schema
  externals.py         # svn:externals 结构化 parser/rewriter
  planner.py           # inspect snapshot -> BranchPlan
  codec.py             # 计划规范 JSON、ID 和严格读取
  validator.py         # URL/revision/同仓库/目标不存在/闭包校验
  applier.py           # SourceRepositoryAdmin mutation batch
  relocate.py          # 受控工作副本 relocate 计划
  result.py            # 结果与审计摘要
```

```python
@dataclass(frozen=True, slots=True)
class BranchPlan:
    plan_id: str
    source_revision: int
    expected_repository_revision: int
    source_root: str
    target_root: str
    copies: tuple[BranchCopy, ...]
    property_changes: tuple[PropertyChange, ...]
```

plan ID 覆盖 schema、源/目标规范 URL、固定 revision、每个 copy、externals 原始摘要与目标值、规则版本
和仓库 UUID。创建 plan 后任何源属性、目标存在性或仓库 revision 变化都导致 apply 冲突并要求重规划。

## 3. externals 与执行语义

- 使用结构化 parser 保留 peg revision、operative revision、相对 URL 形式、引号路径和行顺序；
- 只重写显式匹配的 URL 前缀，未匹配 external 要么按策略保留，要么规划失败，不能静默猜测；
- 重写后 external 必须仍在允许仓库集合，目标路径不得重复、逃逸或大小写冲突；
- source/project/resource/custom mappings 全部是配置数据，禁止正则替换完整文件；
- 同仓库 copy 与 propset 组成一个原子 mutation batch；适配器不能分多次提交留下半分支；
- mutation ID 幂等：相同 ID/相同 plan 返回原结果，相同 ID/不同 plan 必须冲突；
- 网络临时失败仅在能证明服务器未提交时重试；结果不确定时进入 `UNKNOWN` 并人工核对 revision；
- relocate 只作用于显式 WorkspaceLease 内的已验证工作副本，不修改源快照或任意用户目录。

## 5. 失败排查与完成标准

| 症状 | 首查证据 |
| --- | --- |
| external 指向旧分支 | 原始属性摘要、mapping 版本、rewrite report |
| apply 前冲突 | expected/current revision、目标存在性、plan ID |
| 操作结果未知 | mutation ID、svn revision 日志、适配器审计 |
| relocate 修改错误目录 | WorkspaceLease root、working-copy snapshot、URL pair |
| 重复创建 | mutation 幂等记录、目标 revision、原 plan |

自动化只证明规划与受控适配器契约。只有一次性仓库的原子写、冲突和恢复证据关闭后，才能启用
非生产 SourceRepositoryAdmin；生产启用还需要独立权限审批和计划 31 灰度门禁。
