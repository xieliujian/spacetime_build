# 资源构建流水线设计

> 当前正式版本制作的范围已调整为十二个独立资源任务，并由 Jenkins 决定执行顺序；
> `story`、角色高级任务、技能任务、低清、分包和 Redirect 不属于第一期。
> 当前实施规格见 `../release_build/00_正式版本资源构建与发布设计.md`，若范围冲突以该规格为准。

## 1. 状态与目标

- 文档状态：**设计完成，独立审查通过**。
- 代码状态：**规划中，`st.build.resource` 尚不存在**。
- 目标：把旧 `ResController` 中混合的 SVN、Unity、资源规则、提交和上传拆为确定性 `BuildTask`。
- 非目标：本模块不写六字段文件列表、不上传 CDN、不激活发布版本、不提交源 SVN。

## 2. 只读参考与已确认行为

只读参考 `resource/res_controller.py`、`resource/res_utils.py`、`resource/scene/`、`resource/subpackage_resource/` 和旧 `readme/00` 至 `07`。已确认旧流程覆盖：

- config/struct、Lua、scene/map/story、character/LOD/expression、shader/variant；
- particle、texture/UI atlas、audio、video、skill/track、EmptyScript；
- 主/低清变体、单任务/多任务和 Unity manifest 依赖采集；
- 旧控制器还会更新/提交 SVN 和上传，这些副作用不迁入资源 Task。

旧 Unity 参数只作为迁移输入，例如 `-BUILD_SCENE`、`-BUILD_MAP`、`-BUILD_STORY`、`-BUILD_CHARACTER`、`-BUILD_SHADER`、`-BUILD_UI`。新系统先建立类型化 `UnityOperation`，仅由 Unity 适配器映射为旧参数。

## 3. 模块结构

```text
src/st/build/resource/
  model.py                 # ResourceKind、Variant、输入和规则版本
  task_base.py             # ResourceBuildTask 公共计划/校验
  unity_operations.py      # 类型化 Unity 操作
  manifest_collector.py    # Unity manifest -> LogicalArtifact 依赖
  blob_committer.py        # 工作区文件 -> 内容寻址 Blob
  aggregation.py           # 多任务产物聚合
  low_variant.py           # 低清输入和 meta 快照策略
  tasks/
    config.py
    script.py
    shader_variant.py
    shader_bundle.py
    scene.py
    map.py
    story.py
    character.py
    character_lod.py
    character_expression.py
    gpu_skin.py
    texture.py
    ui.py
    particle.py
    audio.py
    video.py
    skill.py
    skill_track.py
    empty_script.py
```

`tasks` 只能依赖 `core`、`ports` 和本包模型。每个任务声明唯一输出所有权、固定工具链、资源规则版本、输入树摘要和是否需要 Unity。

## 4. 输入与输出

```python
@dataclass(frozen=True, slots=True)
class ResourceBuildInput:
    source_snapshot_id: str
    resource_snapshot_id: str
    platform: BuildPlatform
    variant: ResourceVariant  # 从 st.build.release.entries 导入唯一枚举
    rule_version: str
    baseline_manifest_id: str | None

@dataclass(frozen=True, slots=True)
class UnityOperation:
    name: str
    project_role: UnityProjectRole
    arguments: tuple[tuple[str, str], ...]
    expected_output_roots: tuple[str, ...]
```

输出全部转换为现有 `LogicalArtifact`：

- `config/`、`script/`、`scene/`、`story/`、`character/` 等保持客户端逻辑路径；
- AB 依赖保留 Unity manifest 原始顺序和重复项；
- Blob 必须先进入持久化内容寻址存储，locator 不得指向临时工作区；
- task 实际输出集合必须与 `TaskSpec.outputs` 严格相等。

本模块禁止重新声明 `ResourceVariant`；`model.py` 必须从 `st.build.release.entries` 导入唯一类型。
`BuildPlatform` 由实施计划 Task 1 新增到 `st.build.core.platforms`，作为资源和 package 共用的唯一平台枚举。

## 5. 任务 DAG

```text
fixed source/resource snapshots
  -> config + struct
  -> shader variant -> shader bundles
  -> scene/map/story -------+
  -> character/lod/expression|
  -> texture/ui/particle ----+-> manifest collection -> resource aggregation -> BuildManifest
  -> lua/audio/video/skill --+
```

任务之间只通过已登记产物传递数据。Shader 共享依赖由显式 shader task 生产；其他任务可以引用，但不能覆盖其 `depend/shader_*` 输出。

## 6. 资源类型边界

| 类型 | 主要输入 | 主要输出 | 特殊约束 |
| --- | --- | --- | --- |
| config/struct | 固定表格快照和转换工具 | `config/`、`struct/` | 文本/二进制确定性、差异目录显式 |
| Lua | 固定脚本树和加密策略 | `script/` | hotfix 入口、加密版本进入身份 |
| shader | variant 输入和 Unity 工程 | `depend/shader_*` | 独占共享依赖输出 |
| scene/map/story | 场景工程、配置和 shader | `scene/`、`map/`、`story/` | 场景依赖和低清输入显式 |
| character | 角色工程、配置和 shader | `character/` | LOD/expression/GPU skin 分任务 |
| texture/ui/particle | 对应工程、atlas/Spine 参数 | `texture/`、`ui/`、`particle/` | atlas 缓存、粒子依赖清理规则版本化 |
| audio/video | 媒体源和工具版本 | `audio/`、`video/` | 大小写与 bank/列表校验 |
| skill/track/empty | UI/技能工程 | `skill/` 等 | 输出所有权不能与 UI 冲突 |

## 7. 主/低清与增量

- 主、低清使用不同 `ResourceVariant` 和 BuildManifest；低清显式引用主 manifest；
- 低清 meta 切换必须发生在隔离工作区，禁止改回源目录；
- baseline 只用于验证/合并，不允许任务读取可变发布目录；
- 目录树哈希按原始字节和大小写敏感逻辑路径计算；
- 缓存命中仍校验 blob 哈希、大小、任务身份和工具链。

## 8. 失败与恢复

- 缺输入、输出冲突和 manifest 不一致：`ArtifactValidationError`，不重试；
- Unity 非零退出、超时或缺结果：`ToolExecutionError`，保存日志位置；
- 任务失败不得提交 SVN、上传或登记部分输出；
- 恢复只复用 `VerifiedFrontier` 验证通过的完整任务；
- 取消停止后续调度并终止对应外部进程，保留诊断记录。

| 症状 | 排查入口 |
| --- | --- |
| Task 没进入 DAG | ResourceKind、TaskPlan、依赖名称和平台/变体过滤 |
| Unity 成功但无产物 | UnityBatchResult、expected roots、manifest collector 日志 |
| AB 依赖缺失 | Unity manifest 原始内容、逻辑路径映射、shader 上游身份 |
| 缓存命中后哈希错误 | TaskIdentity、Blob locator、重新计算的 SHA256/size |
| 低清污染源目录 | WorkspaceLease、输入/输出树哈希和 low transformation plan |
| 聚合输出冲突 | 每个 TaskSpec.outputs 与 fan-in ownership 表 |

## 9. 测试与验收

- 纯 Python 任务：真实小型目录 fixture 和字节级输出；
- Unity 任务：先用假 Unity 固定命令/结果契约，再在隔离 Unity fixture 项目验证；
- 资源类型：每类至少有成功、缺输入、工具失败、输出污染和取消用例；
- 主/低清：验证身份、输出隔离和主依赖；
- 迁移：旧系统隔离副本与新任务对同一快照双跑，比较客户端逻辑路径、哈希、大小和依赖。

## 10. 完成标准

全部资源类型有唯一 Task、明确输入输出和排查方式；BuildManifest 可从任务产物确定性创建；资源阶段不产生发布和 SVN/CDN 副作用。真实 Unity 与迁移验收未完成前不得宣称资源打包可用。
