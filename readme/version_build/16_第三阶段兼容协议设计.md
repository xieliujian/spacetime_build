# 第三阶段兼容协议设计

## 1. 目标与范围

本阶段在既有 `release` 领域模型之上实现旧客户端文本协议，不执行
Unity 构建、SVN 操作、CDN 上传或版本入口激活。

本次交付包括：

- 显式 LF/CRLF 换行策略；
- 六字段文件列表 DTO、writer 和严格 parser；
- AssetBundle 数据库 DTO、五库路由、writer 和严格 parser；
- 覆盖 main/low、历史 URL、依赖重复和 Redirect 的合成 Golden；
- compatibility 专项测试、全仓质量门禁和阶段文档更新。

真实历史五库、main/low 文件列表、旧系统隔离双跑和旧客户端 parser 验证不在本次
交付范围内。对应证据文件保持 `PENDING`，不得把合成 Golden 描述为迁移验收结果。

## 2. 依赖边界

依赖方向固定为：

```text
compatibility
  -> release
  -> core.errors
```

`release` 与 `core` 不得反向导入 `compatibility`。兼容层只接收已经通过领域校验的
`ReleaseManifest` 或 `ReleaseSnapshot`，不读取构建输出目录，也不重新实现发布领域
模型。

`ReleaseSnapshot` 必须只能经 `ReleaseSnapshot.create` 创建。其 dataclass 使用
`init=False` 和不存储在实例字段中的私有构造令牌；直接构造及
`dataclasses.replace` 均失败，避免 compatibility 接收绕过集合级校验的快照。

writer 和 parser 是纯内存 bytes 转换器。它们不得使用平台默认编码、默认换行、
`Path.write_text()`、SVN、Unity、Jenkins 或网络接口。

## 3. 模块结构

```text
src/compatibility/
├─ __init__.py
├─ line_endings.py
├─ file_list_dto.py
├─ file_list_writer.py
├─ file_list_parser.py
├─ assetbundle_dto.py
├─ assetbundle_routing.py
├─ assetbundle_writer.py
└─ assetbundle_parser.py
```

文件列表和 AssetBundle 数据库分别拥有独立 DTO、writer 与 parser。两类协议只共享
换行策略和 `CompatibilityError`，不引入通用文本序列化框架。

### 3.1 公共 API

`compatibility` 只导出：

- `LineEnding`；
- `FileListRow`、`file_list_rows_from_manifest`、`LegacyFileListWriter`、
  `LegacyFileListParser`、`ParsedFileListRow`；
- `client_databases_from_release_snapshot`、`LegacyAssetBundleDbWriter`、
  `LegacyAssetBundleDbParser`；
- `ParsedAssetBundleDatabase`、`ParsedAssetBundleRecord`、`ParsedRedirectRecord`。

writer 专用的 `AssetBundleRecord`、`AssetBundleRedirectRecord` 和
`AssetBundleDatabase` 使用不可重放构造机制，只允许快照转换工厂创建；直接构造及
`dataclasses.replace` 均失败，也不从包入口导出。

## 4. 六字段文件列表

### 4.1 数据来源

`file_list_rows_from_manifest(manifest)` 只遍历具有
`ReleaseMembership.FILE_LIST` 的快照条目：

- 普通文件和未 Redirect 的 AssetBundle 进入文件列表；
- `REDIRECT_SLICE` 原始 AssetBundle 不进入文件列表；
- Redirect 容器按唯一逻辑路径进入一次；
- 每个 `ReleaseEntry.list_version` 必须等于 manifest 的当前 `file_list_no`，
  转换时使用该一致值作为 FileVersion；
- `source_md5` 始终表示原始逻辑文件 MD5；
- `transfer_size` 表示客户端下载的实际传输对象大小，并始终作为 FileSize；未压缩
  对象的传输规划器必须保证其等于 `original_size`，zip 对象允许二者不同；
- `file_url` 必须是规范的客户端相对 URL：严格等于
  `quote(f"{object_version}/{logical_path}", safe="/")`，zip 传输对象再追加
  `.zip`；CURRENT_UPLOAD 与 HISTORICAL 都使用各自已有 `object_version`，因此历史
  对象仍保留历史目录。六字段 DTO 同时拒绝 Tab、CR、LF 和无法严格编码为 UTF-8
  的值；
- `subpackage_flag` 原样写入非负 Int32 字段。

转换器不得压缩文件、重算哈希、修改 URL 或推导分包归属。它只验证传输对象规划器
已经写入的 URL：`source_blob == transfer_blob` 且大小相等时必须使用原始逻辑路径；
传输身份不同时视为 zip 对象并要求 `.zip` 后缀。URL 不符合上述确定性规则时抛出
`CompatibilityError`，不得静默修正。

`FileListRow` 是 writer 专用不可变 dataclass，只能由
`file_list_rows_from_manifest` 的私有绑定函数创建；直接构造及
`dataclasses.replace` 均失败。字段与类型固定为：

- `file_name: str`；
- `file_version: int`；
- `file_size: int`；
- `file_md5: str`；
- `file_url: str`；
- `file_subpack_id: int`。

### 4.2 writer

`LegacyFileListWriter` 显式接收 `LineEnding`，输出 UTF-8、无 BOM 的 bytes：

```text
FileName<TAB>FileVersion<TAB>FileSize<TAB>FileMD5<TAB>FileUrl<TAB>FileSubpackID
```

记录按 `file_name.encode("utf-8")` 升序排列。非空输出的最后一行也必须带指定换行；
空输入输出 `b""`。

整数使用规范十进制：0 写作 `0`，正整数首位不得为 0，不接受正号、负号或前后空白。

### 4.3 parser

`LegacyFileListParser.parse(data, *, expected_list_version=None)` 返回独立的
`tuple[ParsedFileListRow, ...]`，不复用 writer DTO 构造入口。
`ParsedFileListRow` 是可公开读取的不可变 dataclass，拥有与 `FileListRow` 相同的
六个字段。parser 严格拒绝：

- BOM、非 UTF-8 和混合换行；
- 非六列、未终止末行和重复 FileName；
- 非法或越界 Int32；
- 非法逻辑路径、非 32 位小写十六进制 MD5，以及字段中的 Tab、CR、LF；
- 调用方指定 `expected_list_version` 后出现其他 FileVersion。

解析错误统一抛出 `CompatibilityError`，消息包含可定位的行号。

文件列表 grammar 为：

```text
positive_int = [1-9][0-9]*
non_negative_int = 0 | [1-9][0-9]*
row = FileName TAB positive_int TAB non_negative_int TAB md5 TAB FileUrl TAB non_negative_int EOL
file_list = row*
```

## 5. AssetBundle 数据库

### 5.1 单向 DTO

AssetBundle writer DTO 只能由
`assetbundle_records_from_release_snapshot(snapshot)` 创建。转换器只接收具有
`ReleaseMembership.ASSET_BUNDLE_DATABASE` 的条目：

- 未 Redirect AssetBundle 保留有序、可重复依赖；
- `REDIRECT_SLICE` 保留原 AB 名和依赖，并引用 Redirect 容器、offset、length；
- Redirect 容器自身恰好出现一次；
- 普通非 AB 文件不得进入数据库。

DTO 构造受模块私有工厂令牌保护，调用方不能用散装字段伪造已经过快照校验的数据库。
转换时还必须对 AB 名、依赖名和 Redirect 容器名执行兼容文本校验：它们必须是合法
客户端逻辑路径，不得包含 Tab、CR、LF，也必须能严格编码为 UTF-8。

writer DTO 固定为：

- `AssetBundleRedirectRecord(container_name: str, offset: int, length: int)`；
- `AssetBundleRecord(name: str, dependencies: tuple[str, ...], redirect:
  AssetBundleRedirectRecord | None)`；
- `AssetBundleDatabase(name: str, records: tuple[AssetBundleRecord, ...])`。

### 5.2 五库路由

旧工程中的真实只读文件
`F:\proj_se\develop\client\project\BuildRes\assetbundledb_*.txt` 表明，
`depend/shader_*.assetbundle` 同时存在于五个数据库中，而不是只属于单一数据库。
因此路由 API 为
`database_names_for_path(logical_path) -> tuple[str, ...]`，允许一条记录复制到多个
独立索引空间。

固定路由为：

- `scene/`、`story/` -> `assetbundledb_scene.txt`；
- `ui/` -> `assetbundledb_ui.txt`；
- `texture/` -> `assetbundledb_other.txt`；
- `character/` -> `assetbundledb_character.txt`；
- `particle/` -> `assetbundledb_particle.txt`。
- `depend/shader_*.assetbundle` -> 上述五个数据库；
- `skill/` -> `assetbundledb_other.txt`；
- `lingren/resources/global/` -> `assetbundledb_scene.txt`。

其他 `depend/` 路径在真实 fixture 证明归属前按未知前缀拒绝，不能从当前 13 个
Shader 样本外推。其他未知前缀同样抛出 `CompatibilityError`。聚合函数签名固定为：

```python
def client_databases_from_release_snapshot(
    snapshot: ReleaseSnapshot,
) -> tuple[AssetBundleDatabase, ...]: ...
```

返回顺序固定为 scene、ui、other、character、particle，结果恰好包含五个固定
数据库；没有记录的数据库仍存在且 writer 输出 `b""`。

每个数据库是独立索引空间。记录的每个依赖目标和 Redirect 容器必须被路由到该记录
所在的同一个数据库；聚合阶段以 `CompatibilityError` 拒绝无法在本库解析的引用。

### 5.3 writer

`LegacyAssetBundleDbWriter` 按 AB 名 UTF-8 bytes 排序并从 0 分配稳定索引，编码：

```text
ab_name<TAB>index
<TAB>Depend:<dependency_index>(<TAB><dependency_index>)*
<TAB>Redirect:<container_index><TAB>offset<TAB>length
```

依赖索引严格保持快照中的原始顺序和重复。空依赖或空 Redirect 不输出对应子行。
同一记录最多有一行 Depend 和一行 Redirect；同时存在时顺序固定为 Depend 后
Redirect。输出前必须验证依赖和 Redirect 目标存在，并拒绝自环或多节点依赖环。
所有整数使用与文件列表相同的规范十进制，Depend 行至少包含一个依赖索引。

### 5.4 parser

`LegacyAssetBundleDbParser.parse(data)` 返回独立只读解析视图，不复用也不暴露
writer DTO 构造入口。空 bytes 表示合法空数据库。非空输入由记录首行以及其后可选的
Depend、Redirect 子行组成；子行不得出现在首条记录之前，不得重复，且同时存在时必须
保持 Depend 后 Redirect。parser 严格验证 UTF-8、换行、从 0 连续且等于记录位置的
索引、合法逻辑 AB 路径、控制字符、引用目标、字段数量、offset 为非负 Int32、
length 为正 Int32、末尾换行和依赖环，错误统一包含行号并抛出
`CompatibilityError`。

解析视图固定为不可变 dataclass：

- `ParsedRedirectRecord(container_index: int, offset: int, length: int)`；
- `ParsedAssetBundleRecord(name: str, index: int, dependency_indexes:
  tuple[int, ...], redirect: ParsedRedirectRecord | None)`；
- `ParsedAssetBundleDatabase(records: tuple[ParsedAssetBundleRecord, ...])`。

AssetBundle grammar 为：

```text
non_negative_int = 0 | [1-9][0-9]*
positive_int = [1-9][0-9]*
record = ab_name TAB non_negative_int EOL
depend = TAB "Depend:" non_negative_int (TAB non_negative_int)* EOL
redirect = TAB "Redirect:" non_negative_int TAB non_negative_int TAB positive_int EOL
entry = record depend? redirect?
database = entry*
```

## 6. 错误处理

所有协议输入错误、非法引用、编码错误和循环依赖统一使用
`core.errors.CompatibilityError`。兼容层不吞掉原始异常，不返回部分解析
结果，也不自动修复非法输入。

领域模型不变量由 `release` 层负责；兼容层只验证协议边界特有规则，避免重复且可能
分叉的校验实现。只有绕过私有构造入口属于 API 使用错误并抛出 `TypeError`；
FileUrl、路径、UTF-8、字段、索引和引用等协议边界错误必须显式转换为
`CompatibilityError`，不得泄漏 `UnicodeEncodeError` 或 `PublishError`。

## 7. 测试与验收

每项行为严格按 RED -> GREEN 实施：

1. 先添加最小失败测试和必要合成 fixture；
2. 运行目标 pytest node，确认因目标能力缺失而失败；
3. 实现使该测试通过的最小生产代码；
4. 重跑目标测试和 compatibility 回归；
5. 最终执行全量 pytest、覆盖率、Ruff、Pyright、compileall 和中文 docstring 门禁。

合成 Golden 覆盖：

- 文件列表 main LF、main CRLF、历史 URL、low LF；
- AB 数据库 scene LF、scene CRLF、有序重复依赖、Redirect。

本次完成标准是“协议代码与合成 Golden 已实现并通过质量门禁，迁移验收未关闭”。
只有后续真实七文件字节级 diff 和旧客户端 parser 验证均成功，才能把迁移证据改为
`VERIFIED`。
