# 美术辅助能力 Implementation Plan

> **For agentic workers:** REQUIRED: Use `superpowers:subagent-driven-development` 或
> `superpowers:executing-plans` 逐任务执行；每个 Task 独立完成 RED、GREEN 和回归。

**Goal:** 把场景烘焙、图集、Alpha、图片和 PSD 等旧美术辅助脚本重构为无导入副作用、确定性、可独立验证的任务组件。

**Architecture:** `st.build.art` 以不可变 ArtTaskRequest/ArtTaskResult 和专用处理器实现纯文件任务；需要 Unity、TexturePacker 等外部工具时只经计划 18 端口。任务只写 WorkspaceLease 输出并提交 LogicalArtifact/ArtReport，不提交 SVN、不发布资源；跨模块编排仍归计划 26。

**Tech Stack:** Python 3.10、pytest、Pillow 10.4.0、psd-tools 1.9.34、Unity、TexturePacker、计划 18 ProcessRunner/UnityBatchRunner/WorkspaceProvider。

## 2. 模块结构与公共模型

```text
src/st/build/art/
  model.py             # ArtTaskRequest、规则、产物和报告
  image_codec.py       # 规范图像读取/写入与 metadata 策略
  image_ops.py         # resize/crop/pad/alpha/split
  atlas.py             # 图集校验、计划和外部工具结果
  psd.py               # psd-tools 图层映射与导出
  scene_bake.py        # Unity 场景烘焙操作
  asset_checks.py      # FBX、粒子、场景等只读检查/修复计划
  report.py            # 确定性 JSON 报告
  task.py              # BuildTask 适配器与输出登记
```

```python
@dataclass(frozen=True, slots=True)
class ArtTaskRequest:
    task_id: str
    operation: ArtOperation
    input_snapshot_id: str
    rule_version: str
    options: tuple[tuple[str, str], ...]

@dataclass(frozen=True, slots=True)
class ArtTaskResult:
    artifacts: tuple[LogicalArtifact, ...]
    report: BlobRef
```

请求不接受任意 callable、命令或输出绝对路径。每个 operation 有固定 schema、输入后缀、尺寸/像素
上限、输出所有权和工具版本。处理器可被计划 20 的资源任务复用，但 `art` 不依赖 `resource.tasks`。

## 3. 确定性、安全和失败语义

- 输入来自固定快照，输出只位于 WorkspaceLease 下；源树前后 hash 必须一致。
- 路径使用 `/` 逻辑相对路径，拒绝逃逸、链接、保留名、重复大小写路径和覆盖输入。
- Pillow/psd-tools/TexturePacker/Unity 版本进入任务身份；颜色模式、ICC/EXIF、alpha、缩放算法、
  PNG 压缩与时间 metadata 策略明确版本化。
- 图像维度、像素总数、PSD 图层数、归档大小和单任务输出数设上限，拒绝解压/解析炸弹。
- atlas 输入与输出稳定排序；禁止 rotation 等兼容选项由策略显式固定，不能依赖工具默认值。
- 外部工具非零退出、超时、缺输出和日志错误转换为 ToolExecutionError，不自动重试。
- 格式、重复名称、越界 crop、非法映射和计划外输出为 ArtifactValidationError，不重试。
- 取消终止受控进程并删除未提交临时输出；已提交 Blob 不可变，可供后续恢复复核。
- 自动修复必须先产生 diff plan；没有明确规则或存在有损变化时只报告，不改文件。

## 4. 能力边界

| 能力 | 输入 | 输出 | 关键验证 |
| --- | --- | --- | --- |
| image ops | PNG/JPEG fixture | resize/crop/pad/alpha/slices | 尺寸、像素 Golden、metadata |
| atlas | 有序 sprites + rule | sheet + data + report | 重名、最大尺寸、边界、工具版本 |
| PSD export | PSD + 映射表 | 命名 PNG 集合 | 图层可见性、bbox、重复路径 |
| scene bake | 固定 Unity 工程 | bake 产物 + Unity log | operation、输出 roots、源树不变 |
| asset checks | FBX/粒子/场景 fixture | diagnostics/可选 fix plan | 规则版本、计划内 diff、幂等 |

表格输入如确需支持，只在 parser 层转换为严格映射；业务处理器不依赖 Excel 应用。重复 item、空路径、
工作表歧义和大小写冲突必须失败。

## 6. 失败排查与完成标准

| 症状 | 首查证据 |
| --- | --- |
| 图像像素 diff | codec/rule/Pillow 版本、颜色模式、resampler |
| atlas 布局漂移 | 输入排序、TexturePacker 版本、AtlasPlan |
| PSD 漏图层 | 可见性、bbox、映射报告、重复输出诊断 |
| 烘焙污染源目录 | WorkspaceLease、source tree hash、Unity operation |
| fix 修改过多 | fix plan、before/after manifest、规则版本 |

完成要求是每项已迁移 operation 都有脱敏 fixture、确定性输出或类型化报告、源目录零修改证明和
独立状态。未取得 fixture 或真实工具证据的旧脚本保持未迁移，不用空壳任务冒充完成。
