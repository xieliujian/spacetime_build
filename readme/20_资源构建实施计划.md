# 资源构建 Implementation Plan

> **For agentic workers:** REQUIRED: Use `superpowers:subagent-driven-development` 或 `superpowers:executing-plans` 执行。每个 Task 独立完成 RED、GREEN、回归和状态记录。

**Goal:** 按 `readme/19_资源构建流水线设计.md` 实现所有资源任务，并从固定输入生成确定性 BuildManifest。

**Architecture:** 资源模型、任务基类、Unity 请求、manifest 解析和 Blob 提交分别实现；每类资源拥有独立 Task 文件与测试。外部副作用只经阶段 4 ports。

**Tech Stack:** Python 3.10、pytest、现有 `st.build.core`/`st.build.release`、阶段 4 ports/integrations。

## 10. 失败排查

| 症状 | 首查证据 |
| --- | --- |
| Task 未进入 DAG | ResourceKind、TaskPlan dependencies、平台/变体过滤 |
| Unity 成功但无输出 | UnityBatchResult、expected roots、manifest collector |
| AB 依赖缺失 | 原始 Unity manifest、逻辑路径映射、shader task identity |
| 缓存命中但校验失败 | TaskIdentity、Blob SHA256/size、工具链摘要 |
| 低清污染 | WorkspaceLease、源树前后哈希、LowVariantPlan |
| 聚合冲突 | 每个 TaskSpec.outputs 与 fan-in ownership |

## 11. 后续入口与完成标准

自动化门禁通过后，计划 21 可消费 BuildManifest；真实 Unity 证据关闭后资源任务达到平台验收；旧系统双跑关闭后对应资源类型达到迁移验收。任何任务不得直接 SVN 提交、Jenkins 触发或 CDN 上传。
